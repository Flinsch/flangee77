Detailed Description

A top-level window: a background/border chrome (see Style) around an internal content area, exposed via get_content_area() (the only place a caller can actually add children, since this is a Compound: fixed internal composition, not arbitrary public children), with a fixed title bar (title text plus a close button) on top of it, draggable (by that title bar) to move it and, by a small grip in its bottom-right corner, to resize it (never below this frame's own effective minimum size, which already aggregates the content area's own children's minimum sizes recursively). The content area fills whatever is left below the title bar and is kept in sync as the frame is resized.

◆ _calculate_minimum_size()

overrideprotectedvirtual

Returns the content area's own effective minimum size, plus this frame's own title bar height on top (width otherwise unaffected: the title bar never needs more of it than the content area itself already does), floored to MIN_WIDTH/_min_height() either way, so this frame's own chrome always has enough room regardless of how small the content area's own minimum size is. What actually keeps the resize handle (see ResizeHandle) from ever shrinking this frame below it.

◆ MIN_WIDTH

float fl7::gui::faces::Frame::MIN_WIDTH = 80.0f
staticconstexprprivate

This frame's own effective minimum width (see _calculate_minimum_size()) never goes below this, regardless of how small the content area's own aggregated minimum width is (e.g., an empty content area's: 0): a floor for the chrome itself (title bar/close button), not the content.
