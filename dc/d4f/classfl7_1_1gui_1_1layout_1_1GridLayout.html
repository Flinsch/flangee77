Detailed Description

This layout keeps its own grid of children, independent of the attached container's own child list (which only ever determines Z-order/hit-testing): built up via add_child(), which places a new child at an explicit row/column, growing the grid first if either is beyond its current extent (see get_row_count()/get_column_count()); a child added directly via Container::add_child() instead isn't part of this grid, so it's simply left wherever it already is, unarranged by this layout. A cell is either empty or holds exactly one child; add_child() asserts that the cell it's given is still empty, rather than silently replacing whatever's already there. Not yet supported: a child spanning more than one row/column.

Arranges that grid into rows and columns: along the horizontal axis, every column is either exactly as wide as the widest effective preferred width among its own cells (a stretch factor of 0 or less; see set_column_stretch()) or a share of whatever space is left over once every such fixed-width column has been accounted for, proportional to its own stretch factor relative to the other stretched columns' (every column's default: see set_column_stretch(), every column then just splits the available width evenly, unless some are explicitly pinned to their own widest preferred width via 0 instead); same idea vertically for rows, independently, via set_row_stretch() (a stretch factor is kept per row/column here, unlike BoxLayout's own per-child one: several cells share a row/column, so a per-child factor wouldn't be meaningful). Every row/column is separated from its neighbors by a fixed get_row_gap()/ get_column_gap(), within a fixed get_padding() kept around the whole grid.

How a child actually sits within its own cell (possibly larger than its own preferred size: filled, shrunk-and-aligned near/far, or shrunk-and-centered) is then up to its own anchor, independently per axis; see BoxLayout's own doc comment for the exact rules, identical here.

None of this ever shrinks a child past its own effective minimum size, though: once a cell (on either axis) becomes smaller than that, the child keeps its minimum size instead and simply overflows the cell, and possibly this layout's own bounds, rather than shrinking further or distorting its content.

Each child's own effective preferred/minimum size is re-queried live on every perform() call, not cached here, same as BoxLayout.

Also reports its own preferred/minimum size (see Layout): the sum of every row's own tallest preferred/minimum height (plus gaps/padding) by the sum of every column's own widest preferred/minimum width (plus gaps/padding), ignoring stretch/anchor entirely: that's the size this grid would occupy if every child actually got exactly its own row/column's preferred/minimum size, which is what a Container with this layout attached reports as its own effective size.

Returns the smallest this grid could ever actually be laid out at without overflowing: the sum, per axis, of every row's/column's own contribution (plus the fixed gaps/padding on that axis), which is either a non-stretched (stretch <= 0) row's/column's own tallest/widest effective preferred extent among its own cells (that's what perform() always gives it, never less), or a stretched one's own tallest/widest effective minimum extent instead (the only ones perform() can actually shrink that far).

void fl7::gui::layout::GridLayout::set_row_stretch ( size_t row,
float stretch )

Sets the given row's stretch factor: 0 or less means its own height is exactly the tallest preferred height among its own cells, not participating in the distribution at all; a positive value (1, the default for every row until told otherwise) means it instead takes that share of whatever height is left over once every non-stretched (stretch <= 0) row has taken its own, relative to the other stretched rows' own factors; same idea as BoxLayout::set_stretch(), just per row instead of per child (several cells share a row, so a per-child factor wouldn't be meaningful here). Either way, purely about the row's own height, independent of whether a given cell's own child actually fills it (that's its anchor's call, not this one's; see this class's own doc comment).
