Detailed Description

Base class for a pluggable strategy that arranges a Container's current children within it (see Container::set_layout()). A Container with no layout attached (the default) leaves its children exactly wherever they've been explicitly positioned/sized, entirely unmanaged; attaching one of these takes over that job instead, kept in sync automatically as the container's children or own size change (see Container::add_child()/remove_child()/set_size()).

virtual ml7::Vector2f fl7::gui::layout::Layout::calculate_minimum_size ( const Container & container) const
inlinevirtual

Returns how large this layout's own strategy would ideally like container to be, given its current children's own effective minimum sizes, queried by Container::_calculate_minimum_size() while this layout is attached, instead of the plain (no-layout) bounding-box calculation it otherwise falls back to. Default: {0, 0} (no particular opinion; a layout that doesn't actually resize/reposition children, e.g., DefaultLayout, has none to report either).

Reimplemented in fl7::gui::layout::BoxLayout.
