Detailed Description

Base class for all GUI elements ("faces"): position/size (relative to its parent), visibility/enabled state, style resolution, and the input-event hooks. Doesn't own children itself (see Collection for that), so a plain face is a leaf. Absolute (screen) position is computed on the fly during hit-testing/rendering traversal, not cached (fine at GUI scale). Knows nothing about drawing/rendering itself, that's entirely up to implementations of render::AbstractRenderer.

Called with this face's freshly resolved effective text style (part of get_effective_style()'s result), letting a concrete face type enforce a fixed, structural requirement of its own type on it, regardless of whatever a theme (or style override) happens to set, e.g., TextField forcing text_style.preserve_whitespace on, since an editable field's displayed text must always be exactly what was typed, never typeset- trimmed. Default: no-op. NOT a general style-tweaking hook: actual appearance (colors, font, chrome, alignment, ...) stays entirely theme- driven. Most face types have nothing to enforce here at all.

virtual const Face * fl7::gui::Face::_get_interaction_state_proxy ( ) const
inlineprotectedvirtual

Returns the face whose checked/hovered/pressed/focused state (see get_effective_style()) should be used to resolve THIS face's theme-based style, or nullptr (default) to use this face's own state as usual. For a passive, non-hit-testable decoration owned by an interactive parent (e.g., a CheckBox's little box glyph, itself disabled so clicks/hover always resolve to the CheckBox as a whole; see CheckBox::Box), this lets that decoration still visually track its owner's state without being interactive (or checkable) itself. Doesn't affect _get_theme_key(), which still determines which role's Style is being resolved in the first place.

◆ _on_mouse_drag()

virtual void fl7::gui::Face::_on_mouse_drag ( ml7::Vector2f delta,
ml7::Vector2f local_position )
inlineprotectedvirtual

Called once per frame, with this frame's real (OS-synced) mouse movement delta and the mouse's current position (both in this face's own local coordinate space, i.e., relative to the absolute screen position, same as local_position in _on_mouse_down()), while this face is the "pressed" face and the mouse actually moved. Default: no-op. Override for drag-to- move/drag-to-resize-style behavior (e.g., Frame dragging itself via its title bar, which only needs delta) or drag-to-select-style behavior (e.g., TextField extending its selection to wherever the cursor now is, which only needs local_position). delta is deliberately the OS-synced delta (see Mouse::get_x()), not the raw device delta (Mouse::get_delta_x()): a dragged face should track the visible cursor 1:1, unaffected by whatever the raw device delta vs. OS pointer-acceleration relationship happens to be.

Reimplemented in fl7::gui::faces::Frame, fl7::gui::faces::TextField, and fl7::gui::TrackControl.

◆ _on_mouse_wheel()

virtual bool fl7::gui::Face::_on_mouse_wheel ( int delta)
inlineprotectedvirtual

Called once per frame, with this frame's mouse wheel delta (see Mouse::get_wheel_delta(); one notch/detent is 1), while the wheel actually moved and this face is either the hovered face itself or one of its ancestors that the delta has bubbled up to (see Shell::update()): routed by hover, not focus (wheel scrolling always targets whatever's under the cursor, same as it does in a browser or any other GUI, regardless of which face, if any, currently holds the focus), starting at the hovered face and walking up get_parent() from there, stopping at the first one that actually consumes it.

Returns whether this face actually consumed the delta: true stops the bubble-up right here; false lets the next ancestor up try it instead. Default: false (no-op, let it bubble further). A face that's always the meaningful wheel target for its area once reached (e.g., TrackControl, even already clamped at an end) should still return true, so an outer scrollable ancestor (e.g., a ScrollPanel it happens to sit in) doesn't also react to the same notch.

Reimplemented in fl7::gui::faces::ScrollPanel, and fl7::gui::TrackControl.

◆ get_absolute_position()

ml7::Vector2f fl7::gui::Face::get_absolute_position ( ) const

Returns this face's absolute (screen) position, computed by walking up the parent chain, netting out each ancestor collection's own get_scroll_offset() along the way, same as Collection::_find_hit_face() and render::DefaultRenderer independently already do while actually hit-testing/drawing this face's descendants: without that, this would return this face's unscrolled, logical position instead of wherever it's actually hit-tested/drawn/visible right now. Not cached (fine at GUI scale, matches the rest of the traversal/hit-testing code).

◆ get_effective_style()

Style fl7::gui::Face::get_effective_style ( ) const

Returns this face's effective style: its own override if set, else this face's own role resolved against the owning shell's theme (using its own checked/hovered/pressed/focused state, see Theme::State, unless _get_interaction_state_proxy() redirects that part to another face, and unless _requires_own_bounds_for_hover() further narrows a proxied hovered state down to this face's own bounds specifically), else, only for a face with no themed role of its own (see _get_theme_key()), the nearest ancestor's explicit override instead (not that ancestor's own effective style, which may itself just be a theme resolution, that's specific to the role of the ancestor, not to the role of this face), so a themed ancestor's override deliberately does NOT reach past a descendant that has its own distinct role (e.g., a Button inside an overridden Panel still looks like a Button), only past anonymous content that has no role to resolve in the first place. Else a default-constructed style as a last resort (no override anywhere up the chain, no theme, or a face type with no themed role).

◆ set_tab_order()

void fl7::gui::Face::set_tab_order ( int tab_order)
inline

Sets this face's explicit Tab-order index: among the Tab stops (see _is_focusable()) being ordered within a top-level face's subtree, one with an explicit index always comes before one without; two explicit indices compare by their value. Either kind of tie (equal explicit indices, or no explicit index at all) falls back to tree/insertion order. Unset by default: most faces just take their natural position in the tree.
