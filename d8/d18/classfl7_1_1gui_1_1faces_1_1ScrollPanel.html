Detailed Description

A Panel-like background/border chrome around an internal, always-present vertical and horizontal ScrollBar plus an arbitrary, publicly addable content area (see get_content_area(), the only place a caller can actually add children, same as Window's), whose content is allowed to be larger than its own (viewport) bounds: scrolled into view via get_scroll_position()/set_scroll_position(), clamped to get_content_size() (set explicitly by the caller: there's no layout system yet to compute a content size from the children themselves, see Container). Overflowing content is still clipped to the content area's own bounds regardless (see Collection::clips_children()). Also scrolls vertically on its own, by get_wheel_step() per wheel notch, while hovered (or bubbled up to from a child that doesn't itself want the wheel (e.g., a Label), but not one that does (e.g., a Slider); see Face::_on_mouse_wheel()).

Both scroll bars are always instantiated, but each can be independently disabled (see set_vertical_scroll_enabled()/set_horizontal_scroll_enabled()) and each has its own, independent visibility mode (see ScrollBarVisibility).

◆ _layout()

void fl7::gui::faces::ScrollPanel::_layout ( )
private

Positions/sizes the content area and both scroll bars for this panel's own current size, and resolves each scroll bar's actual shown/hidden state (see ScrollBarVisibility) and enabled state (shown and its own axis is enabled) for this pass. Auto visibility is resolved against each axis's own full-size overflow first, then re-checked once more for whichever axis wasn't needed on its own, against the viewport as actually reduced by the other axis's scroll bar (if that one did end up shown): sufficient to converge for exactly two axes.
