Detailed Description

A closed, non-editable selection widget (like an HTML <select>): shows the currently selected item's text plus a trailing arrow glyph, and, while clicked/ Enter/Space-activated open, a popup list of all items to choose from (see add_item()). Unlike an editable combo box, there's no free-text entry, so the selection is always exactly one of the added items, or none.

Internally a small fixed composition (see Compound), same as ScrollBar's own track + buttons: a disabled Label for the current text (so a click/hover over it resolves to this DropDown as a whole, same trick as CheckBox's caption) and a genuinely interactive trailing Button of its own (an arrow glyph), which opens/closes the popup just like clicking the text part does, but keeps its own distinct hovered/pressed look (and its own Tab stop/Enter-Space activation) while actually being clicked/focused specifically.

The popup is a separate top-level Shell face (see Collection::clips_children()'s doc comment on why: it must be free to escape this DropDown's own logical owner's bounds), created lazily on first open and simply hidden/shown again afterwards, never destroyed again (Shell has no way to remove a top-level face at all, same as, say, a Window); see Shell::open_popup()/close_popup() for how its Z-order/auto-close-on-focus-elsewhere is kept in order regardless. Note: _arrow_button being its own genuine Tab stop (same as any other Control) means it, not just this DropDown itself, can end up focused. Only while THIS DropDown itself is the focused face do Escape/Up/Down actually move the popup's selection (see _on_key_down()/_consumes_arrow()); while _arrow_button specifically holds focus instead, only Enter/Space (toggling it via its own _on_click(), same as any Button) does anything.

Keyboard focus never moves onto the popup itself, though: arrow keys always move its selection from whichever of the two above actually holds focus instead, so a stray click into the popup list (which Shell's normal mouse handling cannot help but focus, see _on_popup_selection_changed()) hands focus right back here afterwards, never leaving it on the popup.
