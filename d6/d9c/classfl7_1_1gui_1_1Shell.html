Detailed Description

The root/driver of a GUI tree: owns top-level faces, routes input, and drives drawing. Deliberately not tied to any OS window: a shell just needs an input source and a renderer, both handed to it by the caller, so it can equally serve as an in-game HUD, a debug overlay, or (each bound to a different player's individual device) a couch-co-op per-player menu.

◆ _bring_to_front()

void fl7::gui::Shell::_bring_to_front ( Face * top_level,
bool restore_focus = false )
private

Moves the specified top-level face (which must actually currently be one) to the back of _top_level_faces, i.e., the front of the Z-order (see update(), hit-tested/drawn last, same as a newly added one would be): the usual "bring the clicked-into window to the front" behavior. A no-op if it's already there.

Also raises, the same way, any registered popup (see open_popup()) whose owner lies within top_level's own subtree: without this, raising a face whose own popup happens to currently sit further back (e.g., some other face having been raised in between) would leave that popup stranded visually behind it, for however long it still takes to actually get closed (its owner's own click handling, e.g., toggling it closed again, only takes effect once that press is released, see update()'s mouse handling): purely a Z-order correction, never closing or otherwise touching the popup itself. Raising the popup itself needs no such chase the other way around.

With restore_focus, additionally moves focus onto top_level itself, resuming wherever it was last left there (or clearing it instead): needed wherever raising doesn't already come with a more specific focus target of its own (see open_modal(); a direct click already knows exactly what to focus instead, see update()'s mouse handling, which leaves this false).

◆ _change_focus()

void fl7::gui::Shell::_change_focus ( Face * face)
private

Changes _focused_face to the specified face (or nullptr), firing _on_focus_lost()/_on_focus_gained() as needed, and resetting the key-repeat timers so a key already held before the new face gained focus doesn't immediately fire a spurious repeat on it. A no-op if face is already the focused face. The shared implementation behind update()'s mouse-press handling, focus_toward(), _focus_adjacent_tab_stop(), and set_focus(). Also remembers a non-null face as its own top-level face's current entry in _last_focused_by_top_level, for _handle_face_hidden() to restore later.

◆ focus_toward()

void fl7::gui::Shell::focus_toward ( ArrowDirection dir,
bool force = false )

Moves focus to the nearest focusable face in the given direction within the current top-level face (the focused face's own top-level ancestor, or, with nothing currently focused, the topmost one), by on-screen geometry, unlike the linear Tab/Shift+Tab (see update()). With force false, a focused face that wants the arrow for itself (e.g., a text caret) keeps it; with force true, only a "hard" consumer (e.g., a list with somewhere left to go) still keeps it. Does nothing if the current top-level face has arrow navigation disabled (see Face::get_arrow_navigation_enabled()), or has no focusable face at all. Called automatically for a plain arrow key press (see update()); exposed publicly so other input (a gamepad's D-pad, say) can drive the same navigation manually.

◆ open_modal()

void fl7::gui::Shell::open_modal ( Face * modal)

Registers modal (which must already be one of this shell's own top-level faces, see add_face()) as a currently open modal, raising it to the front of the Z-order (see update()) and keeping it there every time this is called again, e.g., on every re-open (same as open_popup()). While registered, update()'s own hit-testing blocks mouse input to everything behind it: a click that misses modal itself (and whatever's in front of it, e.g., a popup opened from within it) hits nothing at all, rather than falling through to whatever's behind. Stacks correctly: with more than one modal open, only the frontmost one (and whatever's in front of it) is ever reachable.

Also moves focus onto modal itself, resuming wherever it was last left there (or clearing it instead, on a first-ever open).

◆ open_popup()

void fl7::gui::Shell::open_popup ( Face * popup,
Face * owner )

Registers popup (which must already be one of this shell's own top-level faces, see add_face()) as a popup owned by owner, bringing it to the front of the Z-order (see update()) and keeping it there every time this is called again, e.g., on every re-open: without this, a popup that was only ever created once and hidden/shown again afterwards (this shell has no way to remove a top-level face at all, see close_popup()) would stay wherever it first ended up in the Z-order, even once some unrelated face has since been brought to front ahead of it.

Also makes this shell close the popup again on its own (see close_popup()), the moment focus moves to a face that is neither the popup nor owner, nor a descendant of either (a plain click elsewhere, Tab/arrow navigation moving on, ...): the common "clicking/tabbing away closes the open dropdown/menu/ ..." behavior, implemented once here instead of by every individual popup- opening face. A click into the popup's own content, or back onto owner itself (e.g., to toggle it closed again), is deliberately NOT treated as "elsewhere", so it doesn't get auto-closed out from under that interaction.

◆ update()

void fl7::gui::Shell::update ( )

Refreshes hover/press/focus state from the bound input source's current-frame state. Must be called once per frame, before drawing. Also routes this frame's keyboard text input/key-downs to the focused face, if any: a held key (any of them, not just the ones a particular face happens to care about) auto-repeats after an initial delay, same as text input already does thanks to the OS. Tab/Shift+Tab and arrow-key navigation (see focus_toward()) work even with nothing currently focused yet, landing on an initial candidate instead. While any modal is open (see open_modal()), mouse input never reaches anything behind the frontmost one, hit or not.
