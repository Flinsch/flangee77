Detailed Description

The root/driver of a GUI tree: owns top-level faces, routes input, and drives drawing. Deliberately not tied to any OS window: a shell just needs an input source and a renderer, both handed to it by the caller, so it can equally serve as an in-game HUD, a debug overlay, or (each bound to a different player's individual device) a couch-co-op per-player menu.

◆ _bring_to_front()

void fl7::gui::Shell::_bring_to_front ( Face * top_level)
private

Moves the specified top-level face (which must actually currently be one) to the back of _top_level_faces, i.e., the front of the Z-order (see update(), hit-tested/drawn last, same as a newly added one would be): the usual "bring the clicked-into window to the front" behavior. A no-op if it's already there.

Also raises, the same way, any registered popup (see open_popup()) whose owner lies within top_level's own subtree: without this, raising a face whose own popup happens to currently sit further back (e.g., some other face having been raised in between) would leave that popup stranded visually behind it, for however long it still takes to actually get closed (its owner's own click handling, e.g., toggling it closed again, only takes effect once that press is released, see update()'s mouse handling): purely a Z-order correction, never closing or otherwise touching the popup itself. Raising the popup itself needs no such chase the other way around.

Returns the nearest focusable face in the given direction from the currently focused face, among top_level's own Tab stops (see Face::_collect_tab_stops()), by on-screen geometry, or nullptr if there's no usable candidate. Without a usable starting point (no current focus, or an invisible one), picks the outermost candidate in that direction instead (topmost for Up, bottommost for Down, and so on), so entering a top-level face for the first time lands on an intuitive face.

◆ focus_toward()

void fl7::gui::Shell::focus_toward ( ArrowDirection dir,
bool force = false )

Moves focus to the nearest focusable face in the given direction within the current top-level face (the focused face's own top-level ancestor, or, with nothing currently focused, the topmost one), by on-screen geometry, unlike the linear Tab/Shift+Tab (see update()). With force false, a focused face that consumes the arrow for itself (see Face::_consumes_arrow(), e.g. a text caret) keeps it; with force true, only a "hard" consumer (e.g. a list with somewhere left to go) still keeps it. Does nothing if the current top-level face has arrow navigation disabled (see Face::get_arrow_navigation_enabled()), or has no focusable face at all. Called automatically for a plain arrow key press (see update()); exposed publicly so other input (a gamepad's d-pad, say) can drive the same navigation manually.

◆ open_popup()

void fl7::gui::Shell::open_popup ( Face * popup,
Face * owner )

Registers popup (which must already be one of this shell's own top-level faces, see add_face()) as a popup owned by owner, bringing it to the front of the Z-order (see update()) and keeping it there every time this is called again, e.g. on every re-open: without this, a popup that was only ever created once and hidden/shown again afterwards (Shell has no way to remove a top-level face at all, see close_popup()) would stay wherever it first ended up in the Z-order, even once some unrelated face has since been brought to front ahead of it.

Also makes this shell close the popup again on its own (see close_popup()), the moment focus moves to a face that is neither the popup nor owner, nor a descendant of either (a plain click elsewhere, Tab/arrow navigation moving on, ...): the common "clicking/tabbing away closes the open dropdown/menu/ ..." behavior, implemented once here instead of by every individual popup- opening face. A click into the popup's own content, or back onto owner itself (e.g., to toggle it closed again), is deliberately NOT treated as "elsewhere", so it doesn't get auto-closed out from under that interaction.

◆ set_focus()

void fl7::gui::Shell::set_focus ( Face * face)

Moves focus directly to the specified face (or, with nullptr, clears it), the same way a click or Tab/arrow navigation would: fires _on_focus_lost()/_on_focus_gained() as needed, a no-op if face is already the focused face. Exposed for a face that needs to hand focus back to itself (or elsewhere) of its own accord, outside of any direct click on it (e.g., faces::DropDown, once its popup list closes: actually clicking into the popup unavoidably focuses it first instead, see update()'s mouse handling).

◆ update()

void fl7::gui::Shell::update ( )

Refreshes hover/press/focus state from the bound input source's current-frame state. Must be called once per frame, before drawing. Also routes this frame's keyboard text input/key-downs to the focused face, if any: a held key (any of them, not just the ones a particular face happens to care about) auto-repeats after an initial delay, same as text input already does thanks to the OS.
